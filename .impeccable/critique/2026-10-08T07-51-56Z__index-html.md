## Design Specificity Verdict

**LLM assessment.** The content structure is authored for this product; the look and the interaction are not.
- **Specific:** module codes as the main identifier, markers such as "Chapitre 2" and "TD 3", exams grouped by academic year, "Avec corrigé" as the only coloured fact, and Algerian academic Arabic.
- **Generic:** swap the data and labels and this is any document portal. Type is the bare system font, colour is one navy on white, and every component is the same thin outlined rectangle.
- **The signature is lost:** the module code was meant to be the one distinctive mark. On the first phone screen it is the smallest of ten outlined boxes.

**Deterministic scan.**
- Source files (four HTML pages and `js/`): 0 findings.
- Six rendered pages at desktop width: 0 findings.
- Same pages at phone width (390x844): 5 findings, all one rule, `body-text-viewport-edge`, all on the yellow sample-data notice (`p.page-width` in `js/layout.js`). False positive: the text measures 16px from the edge because the paragraph carries its own padding, and the notice is temporary.
- The detector found none of the priority issues below; they are about flow and density.

**Visual overlays.** The browser was headless, so no user-visible overlay exists. The in-page detector ran on six pages and reported the same result as the scan.

## Overall Impression

Calm, legible and honest on desktop. On a phone the page spends its first screen on itself. The biggest opportunity is to get a document onto the first phone screen, then make each row one tap.

## What's Working

- **The module row.** Aligned code, full name and count, separated by rules. Students recognise the code they already say aloud, and "Aucun document" on GP saves a wasted tap. It survives Arabic intact.
- **States and wording.** Every empty, no-match and failure state is different, in plain French, with a next step. The reset button appears only when a filter is set.
- **Arabic and shareable addresses.** One stylesheet serves both directions, tab arrow keys are mirrored, and the tab, filters, query and language all live in the address.

## Priority Issues

**[P1] On a phone, the Examens tab shows no exam on the first screen**
- **What:** measured at 375x812 with the sample notice present: header ends at 164px, breadcrumb at 316, title block at 479, tabs at 615, filters at 790. The first exam title starts at 879 and its "Voir" button at 980, below the 812px screen. In Arabic the button is at 1071. Without the temporary notice the title is still at 818.
- **Why it matters:** this is the main task on the main device, on every visit. The page reads as empty.
- **Fix:** phone header in two rows; drop the current-page crumb (it repeats the title below it) and the one-item breadcrumb on home; keep the code on the title's first line (`css/styles.css`, `.page-header h1`); tabs four across; the two filters side by side. Target: first document row by about 480px.
- **Suggested command:** `/impeccable adapt`

**[P2] The document row is tall and its title cannot be tapped**
- **What:** the title is a `<p>` (`js/resource-list.js`). Two equal outlined buttons take their own line. Facts are bordered pills that look like buttons. Rows are 166 to 215px tall on a phone.
- **Why it matters:** people tap titles. A 22-document module is many screens of scrolling, and no action stands out as the main one.
- **Fix:** make the title the "Voir" link, keep one "Télécharger" button, put the facts on one quiet text line with "Avec corrigé" as the only badge. This changes two choices recorded in `docs/design-system.md` (two equal buttons; facts as tags), so it needs the maintainer's agreement. The maintainer asked for both viewing and a download button; keep both functions.
- **Suggested command:** `/impeccable distill`

**[P2] Nothing says who runs the site or how to report a problem**
- **What:** the footer repeats the header (`js/layout.js`). "Fichier indisponible" has no next step. There is no update date, no status (official or student-run) and no contact.
- **Why it matters:** students decide whether to trust a corrigé before an exam, and the single maintainer depends on them to flag wrong or missing files.
- **Fix:** use the footer for maintainer, status, last update and one "Signaler une erreur" link, repeated beside "Fichier indisponible". These facts must come from the maintainer; do not invent them.
- **Suggested command:** `/impeccable clarify`

**[P2] Four small defects in rows and states**
- **Arabic size tag:** drawn with the digit separated from its unit (`js/resource-list.js`, `js/i18n.js` `file.size`). Isolate "PDF" and the size separately.
- **Late size tag:** added after the file check (`js/resource-list.js`), it makes rows grow by 24 to 32px. Reserve its space; do not add a size field to the catalogue, which must stay one simple entry per PDF.
- **Session filter:** offers a session the module has no exams for (`js/module.js`). Build its options from the data, as the year filter already does.
- **Duplicate messages:** "Aucun résultat pour « zzzz »." appears twice (`js/search.js`), and "Aucun examen" sits above "Aucun examen ne correspond à ces filtres." (`js/module.js`).
- **Suggested command:** `/impeccable harden`

**[P3] The module code does not read as a signature**
- **What:** the code, tags, tabs, buttons, selects and search field share one outline. Things you can tap and things you cannot look alike.
- **Why it matters:** tappable things are harder to spot, and the site has no memorable face when shared.
- **Fix:** keep outlines for controls only, make tags plain text, give the code its own stronger treatment, and mute tabs that have zero documents.
- **Suggested command:** `/impeccable bolder`

## Persona Red Flags

Task: find the ASD3 exam of January 2025 and open it.

**Casey (phone, limited data).** The module opens on Cours, not Examens. After tapping "Examens" there is no exam on screen. Tapping "Examen de janvier 2025" does nothing. The header costs 164px on every page. The fastest path found is searching "asd3 janvier 2025", which needs 17 typed characters.

**Alex (returning student in exam week).** Every visit restarts at home. There is no visited colour across 22 PDFs and no "Examens" shortcut on the home rows. Searching "asd3" lists all 22 documents with exams last. The direct address `module.html?id=asd3&type=examen` exists but nothing shows it.

**Sam (keyboard and screen reader).** The flow completes, and each link names its document. But there are two tab stops per document, so reaching row N takes 2N presses, and titles are not headings. The search status updates after every typing pause, which is probably chatty; not tested with a real screen reader.
