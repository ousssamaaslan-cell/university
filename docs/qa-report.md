Found and fixed while testing:

1. **The word "false" appeared in the header and under the session buttons.** A part that does not apply was passed to the page as the value `false`. Such parts are now left out.
2. **Searching "asd3 td 3" listed every TD of ASD3,** as the site's search once did. A number after its word must now be the document's own number, and a number alone must be a whole number of the document.
3. **A file of 50,000,001 bytes was said to weigh "50 Mo" for a limit of "50 Mo".** The weight in a refusal is now rounded up: "50,1 Mo".
4. **After any failed deletion the confirmation could only be closed.** It now stays usable after a lost connection or an expired session, and is closed for saving only when the list is out of date.
5. **"Examen" was clipped in its button at 320px.** The four types make two rows of two there.
6. **The bar of ticked rows was 147px tall on a phone.** Its two buttons now share a line: 95px.
7. **The "Termes recommandés" link was 19px tall.** It is now its own line, 46px tall, as is the Netlify link after a timeout.
8. **A field reached with Tab could sit against the window's lower edge with its focus ring cut.** The page now keeps a margin there.
9. **"Publier" showed light text on a light fill for a tenth of a second when it became available,** which axe-core reported. The filled buttons no longer fade.
10. **A line of the missing list had its bullet beside its last line.** The list has no bullets.
11. **A single deletion was reported in the plural.**
12. **On the published site, a replaced PDF would never have been reported online.** Found after the push, by looking at the published PDF's headers. Netlify sends PDFs compressed, and the length a browser is given is that of the compressed copy: 190,904 for the 210,089-byte file. The check compared that length with the file's size, so it would have ended on "Toujours en cours de déploiement" every time. The stand-in announced the true size, which is why the browser run passed. The check no longer uses the length: while the server's mark of the content (its ETag) is unchanged the old file is still served, and once it changes the file is read once and compared with the one that was sent. Fixed in a follow-up commit, with a test that announces a wrong length.

Seen on the published site and not changed, because it is a student page:

- **The module page shows "PDF" without a size.** In Chrome, on `module.html?id=poo1`, the header request for the PDF comes back compressed and without a length the page can read, so `js/files.js` shows no size (on a local server it shows "PDF, 210 ko"). The link and the download are unaffected. The dashboard shows 210 ko, read from GitHub. Whether to show the true size on the public page, and how, is for a later change to the student pages.

Limits to know:

- **The stand-in is not GitHub, and its login page is not Netlify.** Every "Passed on the stand-in" above shows that the dashboard sends the right requests and handles each answer, not that GitHub or Netlify give those answers. Finding 12 is an example of the difference. The reading requests were also made to the real GitHub; the writing ones were not.
- **Requests that left this computer:** the read-only requests to GitHub's API described above, one of them with a made-up token to see GitHub refuse it; axe-core 4.10.2, loaded from cdnjs into the test browser only; lookups of Netlify's documentation and of the npm registry; and, after the push, GET and HEAD requests to the published site and one visit to its public POO1 page in the test browser. - **"En ligne ✓" means the public catalogue shows the change.** If somebody else changes the same document before Netlify has published, the watch ends on "Toujours en cours de déploiement" although the site is up to date.
- **Two saves at the same moment from two tabs:** the second one is retried once on top of the first. If both touch the same document, the second is refused.

## For the maintainer to decide

Nothing here was changed. The first two are points where a reviewer disagrees with a design decision already made.

- **Muted tabs (resolved after Phase 4).** An empty tab now keeps the normal edge; only its label and weight are muted.
- **Purple for opened titles.** In light mode the purple and the link blue are equally dark (7.8:1 and 7.9:1), so only the hue differs. A clearly lighter or darker purple would hold up better in sunlight and for colour-blind readers.
- **A jump to Semestre 4 on the phone home page.** S4 is two screens down. Once it has modules, two small links ("Semestre 3", "Semestre 4") under the introduction would save that scroll.
- **"Signaler une erreur" (resolved after Phase 4).** It now opens a Netlify report form, with the module and document filled in for a missing PDF. The maintainer address is absent from site source.
- **Language memory (resolved after Phase 4).** Only clicking the language switch saves the choice.
- **Link previews (partly resolved after Phase 4).** Static French Open Graph and Twitter defaults and an image are on every page. A distinct preview per module would still need one static HTML page per module.
- **Search by a bare number.** "2024" finds both academic years that contain it, and a number without its word ("asd3 3") still matches the 3 of "ASD3".
- **A module code longer than about seven characters** would misalign its row. None exists.
