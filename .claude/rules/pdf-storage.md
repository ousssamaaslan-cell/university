# PDF Naming And Storage

Store PDFs under `pdfs/<semester>/<module-id>/`, with semester `S3` or `S4` and module ID exactly matching `data/resources.json`. Use lowercase ASCII hyphenated filenames named after the resource ID, such as `asd3-td-03.pdf` or `asd3-examen-2024-2025-emd.pdf`; keep the `.pdf` extension lowercase. Avoid spaces, accents, `#`, `?`, and case-only filename differences so static hosts and URLs behave consistently.

Each published resource must have a relative `pdfPath` that points to an existing, nonempty PDF in the matching folder. Keep the path free of a leading slash so page links stay relative. Verify that the file opens in a browser and downloads. Never expose a local machine path, Drive URL, or placeholder file as a published PDF. Generated placeholder PDFs are allowed only for build-phase `sample-` records (see `docs/project-brief.md`); name them with a `sample-` prefix and remove them before publication. On rename or deletion, update the catalogue in the same change and recheck all affected links.
